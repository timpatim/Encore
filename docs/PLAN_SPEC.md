# H3 Clip Plan — file format specification (version 7)

This document is written for both people and language models. It defines the JSON file that
Encore reads to make a video with MiniMax H3 in ComfyUI (the ComfyUI-H3-ClipPlan nodes read the same format). A machine-readable version is in
[`plan.schema.json`](plan.schema.json). Two complete examples, with their images and song in the same folder:

- [`../examples/robot_beach.plan.json`](../examples/robot_beach.plan.json): a short instrumental music video (`music_video` mode);
- [`../examples/robot_workshop.plan.json`](../examples/robot_workshop.plan.json): a spoken scene (`free` mode).

## 1. What a plan is

A plan describes one video as an **ordered list of clips** generated by MiniMax H3. For each
clip it says how long it is, whether it continues the previous shot, and what it shows, in plain
words. The plan declares its **subjects** once (the characters, places, objects, outfits, styles,
actions and poses the video reuses) with the pictures and voices they come from; a clip names them
with `@name`. The H3 prompt itself, with its numbered `<Subject N>`, `<Picture N>` and `<Audio N>`
and its six sections, is **composed** by Encore (section 6): nobody writes MiniMax's wording by
hand, unless they want to (`prompt_override`).

A plan has one of two **modes**, for the whole project:

| | `music_video` | `free` |
|---|---|---|
| Sound | a song supplied by the user, injected into every clip and kept untouched | generated by H3 with the picture: dialogue, voices, ambience |
| What H3 generates | the picture only, synchronised to the song | picture and sound together |
| Characters' voices | not used (the singing is in the song) | optional voice samples, one per character |
| Spoken / sung words | in the song; the prompt repeats them for lip sync | written in the prompt; H3 speaks them |
| Final soundtrack | the original song | the generated sound of each clip, joined at the same places as the picture |

Background music that does not drive the picture is not part of a plan: add it afterwards in a
video editor.

The plan does **not** contain any start time. Clip positions are computed from the clip lengths
(section 4). Change one length and every later clip moves with it.

A plan names its **files** with labels (`robot`, `beach`, `robot_voice`). Encore gives each label a
`file` path in the project (the « Images to supply » list fills the labels a plan declares without
one) and sends the files to ComfyUI itself. The picture size is a setting of the branch.

## 2. Top-level object

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `version` | integer | yes | | `7`. Older versions (prompts written with `{picture:NAME}`) are refused: rewrite them with subjects. |
| `project` | string | yes | | Short name (letters, digits, `_`, `-`). Output goes to `output/h3_clip_plan/<project>/`. |
| `mode` | `"music_video"` or `"free"` | no | `"music_video"` | See section 1. |
| `clips` | array | yes | | 1 to 64 clip objects, in playing order (section 3). |
| `files` | object | no | `{}` | File label → `{"kind": "image" \| "voice" \| "video", "file": "path", "note": "..."}`. Labels use letters, digits, `_` and `-` and are unique across kinds (`robot` and `robot_voice`). `file` is optional (the path Encore uses); `note` says what the user must supply. |
| `subjects` | object | no | `{}` | Subject name → definition (section 3.1). A name uses letters (any alphabet), digits, `_` and `-`; clips write it `@name`. |
| `width`, `height` | integer | no | | Fallback picture size, multiples of 32, both or neither. Normally left out: Encore uses the size of the branch. |
| `context_frames` | integer | no | `39` | Frames shared by a clip with the end of the previous one. Keep `39`. In `free` mode only 39, 90, 141, 192 or 243 are allowed (section 4). |
| `crossfade_frames` | integer | no | `0` | `0` = hard cut at every seam. `1` to `context_frames` = linear picture blend over that many frames at every seam. |
| `audio_feather_ticks` | integer | no | `8` | `free` mode only. Length, in 25 ms steps, of the soft release at the end of the sound copied from the previous clip. `8` = 0.2 s. |
| `seed` | integer | no | | Base seed. Clip *i* uses `seed + i`. Without it, each clip gets a stable seed derived from the project name. |
| `ref_image_size` | `"match"` or `"max"` | no | `"match"` | Passed to the H3 reference encoder. |
| `song` | object | `music_video` only | | `file` (string, informational) and `duration_seconds` (number, lets a checker verify that the plan fits in the song). Forbidden in `free` mode. |
| `start_video` | object | no | | Clip 1 continues (or cuts from) a segment of an existing video: section 5.1. |
| `edit_video` | object | no | | `free` mode: every clip edits its slice of a segment of an existing video: section 5.2. Not with `start_video`. |
| `notes` | string | no | | Free text, ignored. |

Keys starting with `_` are ignored everywhere and can hold comments. Any other unknown key
produces a warning.

## 3. Clip object

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `frames` | integer | yes | | Raw clip length at 24 fps. Must be `17k + 5` and greater than `context_frames`. |
| `summary` | string | | | One paragraph: what the clip shows. Names subjects with `@name`. |
| `description` | string | | | Style sentences, then the shots: `[Shot 1] ...`, `[Shot 2] At 00:04.000, ...`. The words heard go in `<d>[Language] words</d>`, after their speaker (`@name`, section 6.1). Without `[Shot N]` the whole text is shot 1. At least `summary` or `description` is required (or `prompt_override`). |
| `soundscape` | string | no | | Diegetic sounds (street, footsteps, room tone). In `free` mode, what H3 makes audible. |
| `music` | string | no | | `music_video`: the current section of the song, no lyrics. `free`: usually empty (`None.` is written). |
| `continue` | boolean | no | `false` | `true`: same shot goes on, the clip starts from the last frames of the previous clip (and, in `free` mode, from its last sound). `false`: new scene, generated from scratch. Must be `false` for the first clip (unless `start_video`). |
| `subjects` | array | no | `[]` | Settings of the subjects in this clip: `{"name", "keep", "voice_keep", "note"}` (section 3.2). The subjects of a clip are the ones its texts mention; this list only tunes them. |
| `anchors` | object | no | | Pictures that fix frames of the clip: `{"first": label, "last": label, "keyframes": [{"at": seconds, "file": label}]}` (section 3.3). |
| `prompt_override` | string | no | | A complete H3 prompt written by hand, used instead of the composed one (section 6.3). |
| `defs` | object | no | | The clip's own `files`, `subjects` and `edit_instruction`, used instead of the plan's for this clip. Encore writes it for clips already generated, so that they keep what they were made with. |
| `name` | string | no | `clip_NNN` | Unique label (letters, digits, `_`, `-`), used in file names. |
| `seed` | integer | no | | Overrides the seed for this clip. Change it to get another take. |
| `lyrics` | string | no | | `music_video`, informational: the words newly heard in this clip. |
| `dialogue` | array | no | | `free`: the lines spoken in this clip, each `{"speaker": "<subject name>", "text": "...", "language": "French"}`. Used by the checker (text present in the clip's texts, speaking rate); a speaker counts as a subject of the clip. |
| `notes` | string | no | | Free text, ignored. |

### 3.1 Subjects

```json
"subjects": {
  "girl":   {"kind": "person", "description": "a ten-year-old girl with a school bag",
             "pictures": [{"file": "girl_face", "role": "face and hair"}, {"file": "girl_coat", "role": "red coat"}],
             "voice": "girl_voice"},
  "street": {"kind": "place", "description": "a quiet street after school", "pictures": [{"file": "street"}]}
}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `kind` | `person`, `place`, `object`, `outfit`, `style`, `action`, `pose` | `person` | What the subject is (a person is any character, a robot included). |
| `description` | string | | Short description, in English. May name other subjects with `@name`. |
| `pictures` | array | `[]` | `{"file": image label, "role": "what it gives"}`. A subject can take several pictures (face from one, outfit from another); one picture can serve several subjects. Without `role`: appearance (person, object), scene (place), outfit, visual style, motion (action), pose. |
| `voice` | voice label | | `free` mode: the voice sample of the character. Ignored in `music_video` mode. A character without voice speaks with a voice H3 chooses. |
| `note` | string | | Free text for the user, ignored by the composed prompt (a note for one clip goes in that clip's `subjects`, section 3.2). |

### 3.2 Subject settings in a clip

| Key | Default | Meaning |
|---|---|---|
| `name` | | The subject. |
| `keep` | `identical` | How closely the clip follows the subject's pictures: `identical` (H3: `fully_preserved`), `partial` (`partially_preserved`), `attribute` (`attribute_transfer`: only what the definition names), `loose` (`weak_reference`). |
| `voice_keep` | `timbre` | How closely the voice follows its sample: `exact` (`fully_copy`), `partial` (`partially_copy`), `timbre` (`reference`), `loose` (`weak_reference`). |
| `note` | | This clip only: added to the subject's definition (`in this clip: wears a cap`) and given as the reason of its retention. |

### 3.3 Anchors

`first` and `last` are the first and last frame of the clip; a keyframe is matched `at` seconds from the
start of the clip (strictly inside it), in the shot that contains that time. The labels are images of
`files`. A clip that continues the previous one (`continue: true`) cannot have a `first` anchor: its first
frames are those of the previous clip.

Legal values of `frames` up to about ten seconds:

| frames | seconds | | frames | seconds |
|---|---|---|---|---|
| 56 | 2.333 | | 158 | 6.583 |
| 73 | 3.042 | | 175 | 7.292 |
| 90 | 3.750 | | 192 | 8.000 |
| 107 | 4.458 | | 209 | 8.708 |
| 124 | 5.167 | | 226 | 9.417 |
| 141 | 5.875 | | 243 | 10.125 |

Longer clips are accepted (260, 277, …) but are slow to generate; a checker warns above 243.

## 4. Timing rules

All times are in frames at 24 fps; divide by 24 for seconds. The rules are the same in both modes.

Every clip except the first overlaps the end of the previous clip by `context` frames, where
`context` is the largest value of the form `17k + 5` that is ≤ `context_frames`, ≤ the previous
clip's length and < the clip's own length. With the default settings this is always 39.

```
raw_start[1] = 0                                context[1] = 0
raw_start[i] = raw_start[i-1] + frames[i-1] - context[i]
visible[i]   = raw_start[i] + context[i]        (= end[i-1])
end[i]       = raw_start[i] + frames[i]
```

- `raw_start` is where the clip begins on the timeline (in `music_video` mode, on the song).
- `visible` is the first frame of the clip that reaches the final video. The overlap before it
  is dropped at assembly (or blended, if `crossfade_frames` > 0).
- The final video lasts `end` of the last clip.

Consequences that matter when planning:

1. **A clip shows `frames - 39` new frames**, except the first clip, which shows all of them.
   A 243-frame clip adds 204 frames (8.5 s) to the video.
2. **Cuts fall on a fixed grid.** If the first clip has `17a + 5` frames, every later clip ends
   at `(5 + 17n) / 24` seconds for some integer `n`: 0.208, 0.917, 1.625, … one step every
   0.708 s. A desired cut time `t` snaps to `n = round((24·t − 5) / 17)`.
3. **`music_video`: the last clip must end inside the song**: `end[last] / 24 ≤ song duration`.
4. **A clip with `continue: false` still has an overlap.** Its first 39 frames (1.625 s) are
   generated and then discarded: a hidden lead-in. It should show its scene fully established
   from its very first frame. In `music_video` mode its prompt covers the song from `raw_start`.
   In `free` mode nobody should speak during the lead-in: start the dialogue after it.
5. **`free` mode: the context must fall on the sound grid too.** H3's sound is cut into 25 ms
   steps and a frame lasts 41.7 ms; the two only line up every 3 frames. A `continue` clip copies
   the previous clip's last `context` frames *and* the matching sound, so `context_frames` must be
   both `17k + 5` and a multiple of 3: 39, 90, 141, 192, 243. Use 39.

## 5. `continue`: same shot or new scene

| | `continue: true` | `continue: false` |
|---|---|---|
| Starts from | the last 39 frames of the previous clip, copied exactly (and, in `free` mode, the matching 1.625 s of sound) | nothing |
| Use for | the same shot going on: same place, same framing, same character state | a new place, a new subject, a cut |
| Seam in the final video | invisible, and inaudible in `free` mode | a cut (or a picture blend if `crossfade_frames` > 0) |
| References | should be the same set as the previous clip | free |
| Regeneration | must be rendered again whenever the previous clip is rendered again | independent |

Design intermediate clips so that they end with motion still in progress (a gesture, a camera
move) when the next clip continues them, and let the last clip of a scene resolve.

In `free` mode, **do not end a clip in the middle of a word**: end each clip with a short silence
(about half a second). The next `continue` clip hears the end of the previous one and goes on from
there; it must not repeat lines that were already said.

### 5.1 Starting from an existing video: `start_video`

```json
"start_video": {"ref": "intro", "start": 3.0, "end": 11.0, "in_assembly": true, "song": "with_video"}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `ref` | string | | Label of the video in `files` (`"kind": "video"`). Encore gives the file of that label. |
| `start`, `end` | number (seconds of the file) | `start`: 0 | The segment used. Its length is snapped to the frame grid (17k + 5 frames at 24 fps): `end` is kept, `start` moves forward by less than 0.71 s. It must last more than `context_frames`. |
| `in_assembly` | boolean | `true` | `true`: the segment opens the final video. `false`: it is only a springboard; the final video starts where clip 1 starts (its first frames are the end of the segment, regenerated). |
| `song` | `"with_video"` or `"after_video"` | `"with_video"` | `music_video` mode, segment in the video. `with_video`: the song starts with the segment (the segment loses its own sound), so clip 1 starts later in the song. `after_video`: the segment keeps its own sound and the song starts when clip 1 shows. |

With `start_video`, clip 1 may have `"continue": true`: it starts from the last 39 frames of the
segment (picture, and sound in `free` mode). With `"continue": false` the segment is followed by a
cut. On the timeline the segment takes frames 0 to its length; every clip comes after it.

### 5.2 Editing an existing video: `edit_video`

```json
"edit_video": {"ref": "source", "start": 12.0, "end": 40.0, "sound": "original",
               "instruction": "the footage becomes a hand-drawn cartoon; the man is replaced by @robot"}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `ref` | string | | Label of the video in `files` (`"kind": "video"`). Encore gives the file of that label. |
| `start`, `end` | number (seconds of the file) | `start`: 0 | The edited segment. The timeline of the plan starts with the segment: frame 0 of the timeline is `start`. The clips that end before `end` edit the video; the next ones continue it (see below). |
| `instruction` | string | | The edit common to the clips, in English. It opens the summary of every clip that edits the video; the subjects it names (`@name`) are subjects of each of them. |
| `sound` | `"original"` or `"h3"` | `"original"` | Sound of the final video: the original sound of the segment (untouched), or the sound H3 made (to change a voice or a line). |

`free` mode only, and not together with `start_video`. Each clip gets the frames of the file under
its own span of the timeline (from `start` + its raw start, `frames` frames, resized to cover the
picture size and cropped in the middle) as **`<Video 1>`**, with the sound of that span as its
soundtrack, which H3 numbers `<Audio 1>` (the voices then start at `<Audio 2>`). A clip that edits a video lasts 2 to 15 s (48 to 360 frames), the length H3 takes for a
reference video. A `continue` clip still starts from the end of the previous (edited) clip; a new
scene is best put where the video itself changes shot. The composed prompt of such a clip says that
the target video is an edited version of `<Video 1>`, then gives the instruction and the clip's
summary: the summary only says what changes in this clip, or nothing.

**After the segment.** The clips that end after `end` do not edit the video: they continue it, from the
last edited clip, like any clip (their composed prompt does not name `<Video 1>`). In the final video
the original sound (`"sound": "original"`) is kept over the edited part only; the clips after it keep
their own sound.

## 6. The composed prompt

Encore composes each clip's H3 prompt from the plan, following MiniMax's prompt guide for the
reference model. Only the files of the clip count, and they are numbered for each clip.

### 6.1 Numbers

- `<Subject N>`: the subjects in the order the clip first mentions them (edit instruction, summary,
  description, soundscape, music), then the speakers of `dialogue` not mentioned yet.
- `(Sk)`: the speaker of each line `<d>…</d>`. Encore finds it in the sentence of the line: the subject written
  `@name (S)` if any, otherwise the speaker of the `dialogue` entry with that text, otherwise the first subject the
  sentence names (a second line in the same sentence: the same speaker). Speakers are numbered `S1`, `S2`… in the order
  they first speak, as the guide asks (`<Subject 3> (S1)` when subject 3 speaks first), and that mention becomes
  `<Subject N> (Sk)`. A voice line uses the same `Sk`. Write `(S)` only where the first subject of the sentence is not
  the speaker: *Turning to @girl, @father (S) says: …*
- `<Picture N>`: the pictures of those subjects, in that order, then the anchors not counted yet
  (first, keyframes in time order, last). A picture without its file stops the clip with an error.
- `<Audio N>`: the sound of the edited video first, when the clip edits one and it has a sound, then
  the voices of the subjects. A voice without its file is left out (its lines removed): H3 chooses
  a voice. In `music_video` mode no voice is used.
- At most 9 pictures, 3 voices and 12 files (the edited video included) per clip.

### 6.2 Sections

| Section | What is written |
|---|---|
| `subject_definitions:` | One line per subject: `<Subject 1> is a character: the girl; in this clip: wears a cap; face and hair from <Picture 1>, red coat from <Picture 2>.` One line per anchor: `<Picture 3> is the first frame of [Shot 1].`, `... is a keyframe of [Shot 2] at 00:04.500.`, `... is the last frame of [Shot 2].` With an edited video: `<Video 1> is the source video for the target video edit.` and, when it has a sound, `<Audio 1> is the synchronized audio track of <Video 1> and is reused in the target video.` One line per voice: `<Audio 2> is the voice-timbre reference for <Subject 1> (S1).` A picture that only defines a subject gets no line of its own. |
| `summary:` | The task prefix, then the clip's summary. The prefix joins, in this order: `video editing`, `video continuation` (a `continue` clip), `keyframe completion` (anchors), `reference generation` (subjects with pictures), `audio reference` (voices), `audio reuse` (the edited video's sound): `[video continuation + reference generation]`. An edited clip opens with `The target video is an edited version of <Video 1>.` and the instruction. |
| `retention_analysis:` | One line per subject: `<Subject 1> (appears in [Shot 1], [Shot 2]): partially_preserved - <note>` (the shots are those that mention it). One line per anchor: `<Picture 3> ([Shot 1] first frame): fully_preserved - ...`. The edited video and its sound, then one line per voice: `<Audio 2>: reference - <Subject 1> speaks with this voice.` |
| `detailed_description:` | The clip's description, with `@name` turned into `<Subject N>`. `[Shot 1]` opens with the continuation sentence of a `continue` clip, or the hidden lead-in sentence of a new scene that is not the first clip (section 4, point 4); then `The shot begins from <Picture N>.` for a first-frame anchor. A keyframe adds `At MM:SS.mmm, the shot's keyframe corresponds to <Picture N>.` to its shot, the last-frame anchor `The shot ends on <Picture N>.` to the last shot. |
| `overall_soundscape:` | The soundscape. |
| `non_diegetic_music:` | The music; `None.` in `free` mode when empty. |

Writing the texts:

- Everything in English, except sung or spoken words and visible text, which stay in their language.
- `description`: one or two style sentences, then `[Shot 1] ...`; later shots `[Shot 2] At 00:04.000, ...`.
  Words go in `<d>[Language] words</d>` after their speaker: `@girl, excited, says: <d>[French] Papa !</d>`.
  - `music_video`: put inside `<d>` the words actually heard in the song between the clip's `raw_start`
    and `end`, including the ones that fall in the overlap.
  - `free`: only the new lines of this clip, in speaking order, with the tone of voice. Do not repeat what
    the previous clip said.
- A `continue` clip first continues what is already happening, then develops it (the opening sentence is
  added for you). Design intermediate clips so that they end with motion still in progress.
- If a mouth must be readable, frame it: medium shot or closer, face toward the camera.
- If a character is on screen but does not speak or sing, say so explicitly.
- `python plan_tool.py prompt my_plan.json 2` prints the prompt composed for clip 2 and its numbers.

### 6.3 A prompt written by hand: `prompt_override`

A clip with `prompt_override` sends that text instead of the composed prompt. Its subjects are the ones
it mentions (`@name`); the pictures, voices and anchors of the clip are numbered as in
section 6.1, and the text uses those numbers: `<Picture N>`, `<Audio N>`, `<Subject N>`. `<Video 1>` only in
a clip that edits a video. A line that names a voice must not name a picture. The six section names
should be there, in order (the checker warns).

### 6.4 Speech length (`free` mode)

French or English speech runs at about 2.5 words per second. Above 3 words per second of new
picture, H3 rushes or cuts lines; the checker warns. Leave room for reactions and pauses.

## 7. Voices (`free` mode)

- A voice sample is a clean recording of the character's voice, 2 to 15 s, ideally speaking
  the language of the plan, without music or other voices.
- MiniMax H3 accepts at most 3 reference sounds per clip, 15 s in all, and 12 reference files
  in all. When a clip uses several voices, each sample is cut to its first `15 / number of
  voices` seconds (7.5 s for two voices, 5 s for three).
- A clip uses the voices of the subjects it mentions. A character without a voice sample is still
  allowed to speak: H3 invents a voice, which may change from one clip to the next.

## 8. Validation checklist

A plan is valid when all of these hold:

1. It is one JSON object with `version` 7 and a legal `project`.
2. `width` and `height`, when present, are both given and are multiples of 32.
3. Every `frames` is `17k + 5` and greater than `context_frames`; in `free` mode `context_frames`
   is 39, 90, 141, 192 or 243.
4. The first clip has `continue: false` (unless `start_video`).
5. Every file has a kind; every subject has a known kind, its pictures are images of `files`, its voice a voice.
6. Every `@name` of a clip (and of the edit instruction) is a subject; every subject setting names a subject,
   once; anchors are images, keyframes inside the clip, no first-frame anchor on a `continue` clip.
7. At most 9 pictures, 3 voices and 12 files per clip.
8. A `prompt_override` only uses the numbers of its clip, and `<Video 1>` only when the clip edits a video.
9. Clip names are unique.
10. `music_video`: the last clip ends at or before the end of the song. `free`: there is no `song`.

Run `python plan_tool.py check my_plan.json [--song-duration 99.4]` to verify a plan and print
its timing table.

## 9. Minimal examples

### 9.1 `music_video`

```json
{
  "version": 7,
  "project": "demo",
  "mode": "music_video",
  "files": {
    "singer": {"kind": "image", "note": "the singer, full body, with the outfit she wears in the video"},
    "street": {"kind": "image", "note": "the cobbled street at night, empty"}
  },
  "subjects": {
    "singer": {"kind": "person", "description": "the singer", "pictures": [{"file": "singer", "role": "face, hair and clothing"}]},
    "street": {"kind": "place", "description": "a cobbled street at night", "pictures": [{"file": "street", "role": "architecture and lighting"}]}
  },
  "song": {"file": "demo.mp3", "duration_seconds": 14.0},
  "clips": [
    {
      "name": "street_a",
      "frames": 209,
      "lyrics": "First line of the song,",
      "summary": "@singer walks down @street at night and starts singing.",
      "description": "The target video is a cinematic night-time music video with soft practical lighting.\n[Shot 1] A medium tracking shot. @singer walks toward the camera along @street. @singer sings with clearly readable mouth articulation: <d>[English] First line of the song,</d> End with the walk and the camera still moving.",
      "soundscape": "Quiet footsteps beneath the song.",
      "music": "The opening verse of the original song, a solo voice over a soft guitar."
    },
    {
      "name": "street_b",
      "frames": 158,
      "continue": true,
      "lyrics": "second line of the song.",
      "summary": "Continue the same unbroken shot: @singer keeps walking and finishes the phrase.",
      "description": "The target video is a cinematic night-time music video with soft practical lighting.\n[Shot 1] @singer keeps singing: <d>[English] song, second line of the song.</d> She stops under a street lamp in @street and looks up as the camera settles.",
      "soundscape": "Quiet footsteps that stop beneath the song.",
      "music": "The opening verse of the original song continues, a solo voice over a soft guitar."
    }
  ]
}
```

Timing: clip 1 covers 0 → 8.708 s. Clip 2 has `raw_start` 170 frames (7.083 s), is visible from
8.708 s and ends at 13.667 s, inside the 14-second song. The composed prompt of clip 2 starts with
`<Subject 1> is a character: the singer; face, hair and clothing from <Picture 1>.` and its summary
with `[video continuation + reference generation]`.

### 9.2 `free`

```json
{
  "version": 7,
  "project": "kitchen",
  "mode": "free",
  "files": {
    "anna": {"kind": "image", "note": "the woman"},
    "anna_voice": {"kind": "voice", "note": "optional: her voice"},
    "kitchen": {"kind": "image", "note": "the kitchen"}
  },
  "subjects": {
    "anna": {"kind": "person", "description": "a woman in her thirties", "pictures": [{"file": "anna", "role": "face, hair and clothing"}], "voice": "anna_voice"},
```
